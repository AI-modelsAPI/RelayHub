# RelayHub UI 全量验证计划（使用者视角，非代码视角）

目标：以真实使用者操作路径，逐页面、逐按钮、逐组件确认功能正常且逻辑正确；数据必须持久化（重启后仍在）。用 Playwright 驱动运行中的管理界面（http://127.0.0.1:8790/），对每一项断言真实 DOM/网络结果，坏的就地修复后复验。

## 验证方式
- 真实浏览器（Chrome）加载 UI，模拟点击/输入/提交，断言页面变化与后端数据。
- 每个用例：操作 → 期望结果 → 实测 → 判定（PASS/FAIL）→ 修复 → 复验。
- 持久化：关键写操作后重启 Core，断言数据仍在。

### 本轮为使用者补齐/修复的缺陷
1. **无法拿到接入信息**：UI 从未暴露网关 Base URL 与本地访问密钥——使用者根本不知道怎么把 RelayHub 接进客户端。新增「设置 → 接入信息」：Base URL 显示+复制、访问密钥生成(只显示一次)+复制+撤销（GET/POST/DELETE /api/v1/keys）。
2. **渠道批量操作无 UI**：已选计数存在但没有任何批量按钮。补批量启用/停用/归档/删除，接 /api/v1/channels/batch。
3. **复制渠道无 UI**：后端有 /channels/duplicate 但列表无按钮。每行补「复制」按钮。
4. **熔断永不恢复(P0)**：渠道触发熔断后永久 circuit open，重启用 Key 也不恢复。修 Available() 冷却后放行探测 + 网关成功回写 RecordSuccess，真实上游复验一次恢复。
5. **macOS 窗口不显示**：壳创建了 WKWebView 窗口但只显示菜单栏。修 orderFrontRegardless + applicationShouldHandleReopen；CGWindowList 确认窗口现 onscreen=1（1100×778）。

### 第二轮（更深的逐组件走查）新发现并修复
6. **编辑渠道会清空凭据（P0，实测复现）**：新建渠道存了 credential_ref，但任意一次「编辑保存」把 credential_ref 覆盖成空——之后该渠道 测试/获取模型/网关 全部 401。根因：saveChannel 编辑分支用空 keys 生成空 credRef 并随 body 覆写。已修：编辑时不再动 credential_ref（Key 由独立的 Key 管理器维护），新建时才按输入 key 生成。实测：编辑后 credential_ref 保留、获取模型 10 条、测试 healthy。
7. **编辑器「获取模型列表」对已有渠道 401**：fetchModels 只读 legacy credential_ref，忽略 per-channel keys（与 test/sync/gateway 不一致）。已统一为「优先启用 Key → 回落 credential_ref」。实测 10 条模型。
- 追加验证 PASS：X3 各页标题、M1 模型搜索、M3 UI 勾选渠道绑定并持久、M4 删除模型、M5 归档持久、C5 编辑回填+备注持久且凭据不丢、C10 状态筛选、C14 映射增删行、C15 标签回车添加、C13 编辑器获取模型、C4 测试 healthy、C16 同步 10 绑定、E3 导入应用刷新、X4 重启后 channels/models/pms 数量不变且 journal=wal。

### 持久化最优解（已落地）
SQLite（modernc 纯 Go）+ WAL + synchronous=NORMAL + foreign_keys=1 + busy_timeout=5s：
- WAL：崩溃/断电安全、读不阻塞写，模式持久化于库文件头；实测重启后 journal_mode=wal。
- synchronous=NORMAL：WAL 推荐级别，防应用崩溃，仅同刻断电可能丢最后一次提交（本地配置数据可接受），fsync 远少于 FULL。
- foreign_keys=1：启动回读断言，未启用则 fail-closed 拒绝启动（修复过 P0-8 静默失效）。
- 密钥/凭据：AES-GCM 密封进 secret_values 表，元数据与密文分离，仅生成时明文出现一次。
- 回归测试 `internal/storage/persistence_test.go::TestWALModeAndPersistenceAcrossReopen` 断言 WAL + 外键 + 关闭重开后数据仍在。
