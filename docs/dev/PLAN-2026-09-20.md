## 0. 两个判断（先写结论）

### 0.1 前后端怎么排期？

**先冻结 API 契约，再并行。不要「同时从零写」也不要「前端全部等后端做完」。**

| 阶段 | 谁 | 为什么 |
|---|---|---|
| **第 0 周：契约** | 一人写 OpenAPI/注释 + 假数据 | 桌面 UI 的每个 Inspector 字段必须有稳定 JSON。没有契约的并行 = 返工 |
| **第 1–3 周：串行补缺口** | **只后端** | 缺口 1/2/5 是正确性问题（流式跨协议、能力标志、401 标记 Key）。UI 画了也是错数据 |
| **之后：并行** | UI 对着冻结的 `/api/v1/*`；后端做 B/C/G | UI 不再发明字段；后端不改响应形状，只加字段（additive） |
| **特性 A/F/D/H** | 后端先最小可读 API，UI 当天就能挂 Inspector | 避免「实验室页面空转两周」 |

禁止：前端自己 mock 一套与 Go 结构体无关的 camelCase 再双向翻译。所有 JSON 继续 **snake_case**，与现有 `api/server.go` 一致。

Wails 壳（真正无边框窗）放在 UI 稳定之后做，避免同时调试 WebView 与业务。

### 0.2 语言：继续 Go 单核，不要换栈

**Core 保持 Go。** 不引入 Rust 网关、不把控制面改成 Node、不用 Python 调度器。

理由（针对这个仓库，不是宗教）：

- 已有 ~25k 行 Go：gateway / router / checkin / browser-CDP / clisync / proxy / secrets，边界清楚。
- 单二进制 + `embed` + SQLite 是 local-first 的正确形状；Docker 也只跑这一个进程。
- 热路径是 HTTP 流式与连接级超时，Go 的 `net/http` 与 goroutine cancel 足够；换 Rust 没有产品收益。
- 签到要 CDP：已经用 Go 控浏览器，不必再嵌一层。

**UI 层：**

| 选项 | 结论 |
|---|---|
| 继续 vanilla JS（`web/`） | **现在采用。** 零构建、与 `embed` 契约简单、可在 :8790 预览。已按桌面范式重写。 |
| Wails v2（Go + 同一套 web） | **桌面发行采用。** 菜单栏进程与 Core 可同二进制或父子进程；Keychain 已有 Swift 桥，Wails 也能调。 |
| Fyne / Gio / Qt | 不采用。控件丑、列表/Inspector 密度达不到规范，且要重写全部 UI。 |
| Tauri / Electron | 不采用。Tauri 把 Core 从 Go 里撕开；Electron 体积与「本机网关」人设冲突。 |
| SwiftUI 全原生 | 仅当 Wails 性能/无边框不可接受时的 macOS 备选；会放弃 Windows/Linux 同一套 UI。 |

**不要 Go 单语言到「用 Go 画 GUI」。** 用 Go 做 Core + 薄桌面壳，UI 用 WebView 画，但是 **按原生应用布局**，不是网站。

## 2. 里程碑

版本按 **可发布切片**，不是按层。

### M0 — 正确性（约 1 周）· 只后端  ✅ 已落地（2026-09-21）

在任何新特性之前：

1. `writeSSE` 按 `protocol` 做 anthropic↔openai 流式翻译；改为流式解析，不再整段进内存。
2. `gateway.go:221` 填 `ToolCallRequired / VisionRequired / ReasoningRequired`。
3. 401 → 标记该 Key disabled（product-roadmap I7 的实质），不再只换渠道。
4. `RequestRecord` 增加 `ttft_ms, finish_reason, upstream_model, cache_read_tokens, cache_write_tokens`。
5. 文档：`ROADMAP-2026` 路由策略段落与 `selector.go:431-463` 对齐。

验收：Claude Code（Anthropic 流式）打 OpenAI 上游不再解析失败；带 `tools` 的请求不会落到无工具渠道。

**UI**：只修壳对现有 API 的字段读取（`channels` / `usage` 包一层）。

### M1 — 钱与号（约 2 周）· 后端 B+C+G，UI 渠道/身份  ✅ 2026-09-21

对应提案 B、C、G，以及旧 `docs/dev/M1-quota-aware-routing.md` 里尚未接线的部分（quota-aware **策略已在 selector**，不要重写）。

后端：

- Session key + 粘性 channel/key + 保留 `cache_control` / `anthropic-beta`
- `resolveChannelCredential` 取消盲目全局 RR
- `Channel.ProxyURL` 接到 gateway / checkin / browser / health
- Identity Bundle 存储
- AIMD 令牌桶读 `Retry-After` / `x-ratelimit-*`；≤2s 本地排队

UI（Channels + Identity + Pulse 英雄数字）：

- 渠道 Inspector 展示粘性会话数、cache hit、学到的 RPM
- 身份页：出口 IP、漂移

并行规则：B/C/G 的 JSON **先合进 GET 响应（空值合法）**，UI 即可画；算法随后填数字。

## 3. 每周节奏（建议 1 人全栈或 2 人）

两人时：**后端主人**拥有 `internal/**` 与 API 形状；**壳主人**拥有 `web/**` 与日后 Wails。契约冲突由后端主人拍板。

一人时：每天上午缺口/特性的 RED 测试，下午把 UI 接到当天新字段。不要一天只写 CSS。

测试：

- Go：`go test ./...` 必须绿。新特性先测包（`internal/verify` 等），再挂 API。
- UI：M0 后补 `tests/web` 对 rail 切换 / ⌘K / 渠道 Inspector 的 DOM 测试（jsdom 或 `node --test` + 正则），**不要**测像素。
- 禁止恢复 `make check-web` 失败却仍合并：`web/` 与 `internal/web/` 继续 byte-identical。
